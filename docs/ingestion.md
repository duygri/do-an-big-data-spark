# NYC Taxi ingestion and Bronze layer

Keep the selected NYC yellow taxi monthly CSV files under `data/raw/nyc_taxi/`. The default configuration selects all six months from January through June 2020; for a smaller run, `input.path` may select one exact monthly file or a subset of those six. The `taxi+_zone_lookup.csv` reference file is optional and enables zone-name enrichment. The `taxi_zones/` shapefile is not used. The default glob excludes 2019 files, and preflight rejects any selected filename outside the supported six-month range. Neither source files nor generated Parquet belong in Git.

Copy `configs/config.example.yaml` to `configs/config.yaml`, then run `python -m src.pipeline.main --config configs/config.yaml` from the repository root. Before Spark starts, preflight requires at least one matching file, rejects directories, duplicate monthly names, files outside January–June 2020, and missing files selected by a multi-month pattern. It accepts one month, a subset, or all six. For example, use `yellow_tripdata_2020-04.csv` for a one-month run or `yellow_tripdata_2020-0[1-6].csv` for the full default window. The generic `read_raw` helper still supports CSV and JSON; the end-to-end cleaning pipeline requires the yellow taxi CSV schema. Input path, header, reader options, Bronze path, Spark master, and maximum file partition size are configurable. Paths are relative to the current working directory. Bronze, Silver, Gold, and reports are overwritten by each run, so their contents match the currently selected input window.

The CSV schema has 18 nullable fields in source order. `VendorID`, `passenger_count`, `RatecodeID`, `PULocationID`, `DOLocationID`, and `payment_type` are integers. Pickup and dropoff datetime are timestamps using `yyyy-MM-dd HH:mm:ss`. `store_and_fwd_flag` is a string. Trip distance and all fare, tax, tip, toll, surcharge, and total amounts are doubles. Blank numeric cells, including early `congestion_surcharge` values, become null. CSV parsing uses FAILFAST for malformed nonblank values; validation and cleaning remain separate team stages. The zone lookup and shapefile are retained as raw reference data but are not loaded by this stage.

The pipeline writes Snappy Parquet to `data/bronze/raw/`, reads it back, and compares its schema and row count with the input. It then cleans Bronze into `data/silver/cleaned/`, writes a quality report, derives trip features, and persists verified output at `data/gold/taxi_trips/`. If `taxi+_zone_lookup.csv` is configured as `input.zone_lookup_path` or found beside the raw CSV files, the pipeline also enriches pickup/dropoff location labels; otherwise it keeps the location IDs and continues. The Gold dataset is partitioned by pickup year and month. It stops Spark on success or failure. See [cleaning and quality policy](cleaning-quality.md), [zone joins](transformation-joins.md), and [processed output](processed-output.md).
